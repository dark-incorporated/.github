# How every Dark Inc. crate is documented

This is the one guide for the README, the `docs/` folder and the media of every repository in [dark-incorporated](https://github.com/dark-incorporated). Each repository's `AGENTS.md` or `CLAUDE.md` links here instead of copying it.

## Why these rules

Each rule below either comes from one of these papers or is labelled house style.

- **Prana et al. 2019**, *Categorizing the Content of GitHub README Files* ([10.1007/s10664-018-9660-3](https://doi.org/10.1007/s10664-018-9660-3)): 97% of READMEs say *what* the project is and 88.5% say *how* to use it, but only about a quarter say *why* it exists, and fewer still give its status.
- **Venigalla & Chimalakonda 2022**, *An Empirical Study On Correlation between Readme Content and Project Popularity* ([arXiv 2206.10772](https://arxiv.org/abs/2206.10772)): links correlate most strongly with popularity, followed by lists, images and code; animated images and video show almost no association.
- **Lee 2018**, *Ten simple rules for documenting scientific software* ([10.1371/journal.pcbi.1006561](https://doi.org/10.1371/journal.pcbi.1006561)): treat the README as the only page anyone reads, make the quick start a demonstration plus a copy-paste stub, let examples double as tests, and automate the checks on the docs.
- **Tan, Wagner & Treude 2023**, *Detecting outdated code element references in software repository documentation* ([10.1007/s10664-023-10397-6](https://doi.org/10.1007/s10664-023-10397-6)): 82.3% of the top 1,000 projects had an outdated code reference at some point, and 28.9% have one now, outdated for 4.7 years on average.
- **Chatlatanagulchai et al. 2026**, *Agent READMEs: An Empirical Study of Context Files for Agentic Coding* ([10.1145/3840295](https://doi.org/10.1145/3840295)): developers maintain agent context files like configuration, with a median of about 500 words at H1 to H3 depth.
- **Gloaguen et al. 2026**, *Evaluating AGENTS.md: Are Repository-Level Context Files Helpful for Coding Agents?* ([arXiv 2602.11988](https://arxiv.org/abs/2602.11988)): context files do not raise task success, they add 20-23% to cost, and files generated by an LLM did worse than none in 5 of 8 settings.

**House style, with no published evidence behind it:** the 250-line README cap, the GIF budgets, and the plain-words rule. They are here because they keep a family of crates consistent, not because a study measured them.

## The README, in this order

1. **Title**: the crate's name.
2. **The Vibe Coded banner**, the same in every repository:

   > ⚠️ **Vibe Coded.** Written by AI agents working from a human's direction, covered by tests rather than a line-by-line human review. Read the code before you rely on it for something you care about.

3. **The pitch**: one sentence saying what the crate does and for whom.
4. **One badge row**: crates.io, docs.rs, CI, Bevy version, licence.
5. **The hero GIF**, with alt text saying what happens and a one-line caption under it.
6. **Status line**: `**Status:** <level> · Bevy <x.y> · MSRV <rust-version>`.
   - The level is `experimental` while the crate is unpublished or at `0.0.x`, and `usable` from `0.1.0`. Nothing is called `stable` before `1.0`.
   - Leave out the MSRV part when `Cargo.toml` has no `rust-version`.
   - Fewer than a quarter of READMEs say when a project is usable (Prana et al.); this line says it.
7. **Why line**: one sentence on why this crate rather than the obvious alternative. Only about a quarter of READMEs give a why (Prana et al.).
8. **Quick start**: the `cargo add` line (a git dependency for an unpublished crate) and at most 20 lines of Rust that compile.
9. **Try it**: one `cargo run --example <name>` that opens the hero GIF's scene.
10. **What you can do**: 3 to 7 bullets of one sentence each, each linking a docs page, with at most 4 inline GIFs.
11. **Part of Dark Inc.**: two sentences linking the [family table](https://github.com/dark-incorporated) and this crate's "use it in the Dark Factory" section of [the book](https://dark-incorporated.github.io/).
12. **Bevy compatibility**: a table of crate versions against Bevy versions.
13. **Learn more**: docs.rs, the book page, `docs/guide/`, the examples and the CHANGELOG. Links are the README feature that correlates most strongly with popularity (Venigalla & Chimalakonda).
14. **Who and licence**: maintainer `@Ladvien`, the issues link, the org's [`CONTRIBUTING.md`](https://github.com/dark-incorporated/.github/blob/main/CONTRIBUTING.md), and `MIT OR Apache-2.0`.

**At least one still image.** Besides any GIF, the README carries one still screenshot or diagram. Still images correlate with popularity; animated images and video show almost no association (Venigalla & Chimalakonda).

## Size (house style)

- A README is at most 250 lines.
- Longer material moves to `docs/guide/*.md`, indexed by `docs/guide/README.md`. Galleries move to `docs/gallery.md`.
- Content is moved, never deleted, and stays in the repository rather than a wiki, so it is versioned with the code (Lee, rule 6).

## Plain words (house style)

- Define each term at first use, in a short clause: "ORCA (optimal reciprocal collision avoidance)", "stigmergy (agents coordinating through marks they leave in the world)", "WFC (wave function collapse)", "SDF (signed distance field)".
- Lead with what the reader gets, not how it works.
- Write features as bullets, and identifiers as inline code.
- Research notes stay out of the README; they belong in `docs/research/`.

## GIFs (house style budgets)

- One idea each: 3 to 8 seconds, looping, at most 960 px wide, 15 fps and 4 MB.
- Alt text says what happens; a one-line caption sits under the GIF.
- Stored in `docs/media/` and never in Git LFS.

## Image and link URLs in a README

A README is shown in three places, and they resolve paths differently: GitHub resolves a relative path against the repository; crates.io rewrites a relative path to `https://github.com/<repository>/raw/HEAD/<path>`; **docs.rs rewrites nothing**, so a relative path in a README that rustdoc includes (`#![doc = include_str!("../README.md")]`) is a broken image there. So:

- Every image in a crate's README is an absolute URL: `https://raw.githubusercontent.com/dark-incorporated/<repo>/main/<path-from-repo-root>`. Every link to a file in the repository is `https://github.com/dark-incorporated/<repo>/blob/main/<path>`. Pages under `docs/` that only GitHub shows may stay relative.
- **A media file is never moved or renamed once a release has shipped pointing at it.** A published README is frozen on crates.io and docs.rs, so its URLs must keep resolving. If one must move, cut a release with the new URLs the same day, so the latest version's pages show it.
- The check is an HTTP one: every `<img src>` on the crate's docs.rs and crates.io pages answers 200. `lychee --offline` only checks what stays relative.

## Videos

- MP4 (H.264) for anything over 8 seconds or narrated: at most 120 seconds and 30 MB, with a poster PNG.
- Videos live only in [the book](https://github.com/dark-incorporated/dark-incorporated.github.io) (`src/media/`), embedded on the crate's page. The README links to that page.

## Reproducible media

`docs/media/README.md` lists every image, GIF and video with the command that regenerates it, the capture date, and the crate version it shows.

Frames come from the repository's own capture path: `bevy_devshot`, an example's capture flag, or Dark Factory's `tools/demo/record.py` with `tools/demo/render.py`. To turn frames into a GIF:

```sh
ffmpeg -framerate 30 -i f_%04d.png -vf "fps=15,scale=960:-1:flags=lanczos,split[a][b];[a]palettegen=stats_mode=diff[p];[b][p]paletteuse=dither=bayer" -loop 0 out.gif
```

## README code is tested, in CI

Add this to `src/lib.rs`, unless the crate already doc-tests its README some other way (as `bevy_gooey` does in `tests/readme.rs`):

```rust
#[cfg(doctest)]
#[doc = include_str!("../README.md")]
struct ReadmeDoctests;
```

- A block that needs a window is marked `no_run`, never `ignore`.
- CI must run the doctests. `cargo nextest` skips them, so a repository whose CI uses nextest adds a separate `cargo test --doc` step.
- CI builds the examples with `cargo build --examples`. Examples double as tests (Lee, rules 2 and 8).

## Docs change in the same PR as the code

In the top 1,000 GitHub projects, 28.9% carry an outdated code reference right now, outdated for 4.7 years on average (Tan, Wagner & Treude). So a change a user can see updates the README and `docs/` in the same pull request, and a feature is not done until its README line and, if it is visible, its GIF exist. The doctests and `lychee --offline` are the mechanical guard.

## Agent context files

`AGENTS.md` and `CLAUDE.md` are written by hand and hold commands and rules, not an architecture tour. Files generated by an LLM did worse than none in 5 of 8 settings, and context files raise an agent's cost by 20-23% (Gloaguen et al.); developers keep them short, like configuration (Chatlatanagulchai et al.). Existing files are not rewritten for this guide; each carries one line pointing here:

> README and docs follow https://github.com/dark-incorporated/.github/blob/main/DOCUMENTATION.md; a feature is not done until its README line and, if visible, its GIF exist.
